The Five-Model Comparator

One engagement, priced five ways

Pick a single engagement below — how many people it replaces, how much work it does, how much value it creates — then watch what the customer pays each month under every pricing model valid for your deployment tier. Nothing about the product changes between the bars. Only the commercial model changes.

Not every model is available everywhere: the CoE reference doc’s Tier-to-Model Mapping (§5.4) restricts each deployment tier to a specific subset of the five models. Change the deployment tier below and watch bars appear and disappear accordingly.

The dashed line is what the customer pays for the humans today. Anything below it is a saving you can share; anything above it needs a very good value story.

Set up the engagement

viewof fteCost   = Inputs.range([30000, 120000], {value: 60000, step: 1000, label: "Human FTE cost (£/yr, fully loaded)"})
viewof fteCount  = Inputs.range([1, 20],          {value: 3,     step: 1,    label: "FTEs replaced / augmented"})
viewof volume    = Inputs.range([100, 10000],     {value: 1000,  step: 100,  label: "Tasks delivered per month"})
viewof value     = Inputs.range([5000, 500000],   {value: 50000, step: 5000, label: "Business value created per month (£)"})
viewof riskScore = Inputs.range([1, 10],          {value: 5,     step: 1,    label: "Risk score (1–10)"})
viewof autonomy  = Inputs.select(["L1", "L2", "L3", "L4", "L5"], {value: "L3", label: "Autonomy level"})
viewof dealTier  = Inputs.radio(
  ["Tier 1 · Internal Use", "Tier 2 · Platform Services", "Tier 3 · Digital Labor"],
  {value: "Tier 2 · Platform Services", label: "Deployment tier"}
)
Tier-to-Model Mapping (CoE reference doc §5.4)
Tier Applicable models
Tier 1 · Internal Use M1 Per Seat (FTE-equivalent transfer price) · M2 Usage (cost recovery)
Tier 2 · Platform Services M2 Usage (API/tokens) · M3 Task · M4 Hybrid — “most flexible tier; can use any model 2–4”
Tier 3 · Digital Labor M1 Per Seat (digital employee) · M3 Task (per deliverable) · M5 Outcome (value share, mature customers only)

M4 is Tier 2-only and M5 is Tier 3-only; M1, M2 and M3 each bridge two tiers but never all three.

Fine-tune each model (optional)

Cost-plus inputs — the raw cost components and cost-recovery margins that build up each model’s base price:

viewof seatDiscount = Inputs.range([0.4, 0.7],   {value: 0.5,  step: 0.05, label: "M1 · seat discount vs human rate"})

// M2 · Tier 1 cost-recovery breakdown (CoE reference doc):
// Internal Price = (Infrastructure + License + Support + Risk Reserve + CoE Overhead) / (1 - Margin)
viewof m2Infra      = Inputs.range([200, 5000],  {value: 1200, step: 100,  label: "M2 · infrastructure cost (£/mo — compute + storage + network)"})
viewof m2License     = Inputs.range([100, 5000], {value: 900,  step: 100,  label: "M2 · license cost (£/mo — vendor fees per agent/API call)"})
viewof m2Support    = Inputs.range([200, 5000],  {value: 1500, step: 100,  label: "M2 · support cost (£/mo — CoE FTE allocation)"})
viewof m2CoEOverhead = Inputs.range([100, 3000], {value: 600,  step: 100,  label: "M2 · CoE overhead (£/mo — governance, training, monitoring)"})
viewof m2Margin     = Inputs.range([0, 0.20],    {value: 0.15, step: 0.01, label: "M2 · margin (0–20%, cost recovery)"})

// M2 · Tier 2 platform-usage formula (CoE reference doc):
// Price per Unit = [(Unit Cost + Allocated Overhead) / (1 - Margin)] + Risk Premium
viewof m2UnitCost   = Inputs.range([0.01, 2],    {value: 0.10, step: 0.01, label: "M2 T2 · unit cost (£/call — infra + license)"})
viewof m2AllocOverhead = Inputs.range([0.01, 1], {value: 0.05, step: 0.01, label: "M2 T2 · allocated overhead (£/call — support+CoE+sales+marketing ÷ expected volume)"})
viewof m2T2Margin   = Inputs.range([0.30, 0.50], {value: 0.40, step: 0.01, label: "M2 T2 · target margin (30–50%)"})
viewof m3Hours      = Inputs.range([0.1, 8],     {value: 1,    step: 0.1,  label: "M3 · estimated hours per task"})
viewof m3Rate       = Inputs.range([15, 100],    {value: 40,   step: 5,    label: "M3 · hourly rate (£/hr)"})
viewof m3Complexity = Inputs.range([1.0, 2.0],   {value: 1.2,  step: 0.1,  label: "M3 · complexity multiplier"})
viewof m4BaseFee    = Inputs.range([0, 30000],   {value: 8000, step: 500,  label: "M4 · base platform fee (£/mo)"})

Value inputs — the levers that tie price to the business value delivered:

viewof m4Share = Inputs.range([0.01, 0.03], {value: 0.02, step: 0.005, label: "M4 · value share"})
viewof m5Share = Inputs.range([0.02, 0.05], {value: 0.03, step: 0.005, label: "M5 · value share"})

Risk / guardrail inputs — the per-model risk loadings (separate from the generic risk/autonomy overlay applied to M1, M2 Tier 1, and M4), plus M5’s ceiling, which guards against renegotiation risk at scale rather than capturing value:

viewof m2RiskRate   = Inputs.range([0.05, 0.10], {value: 0.07, step: 0.01, label: "M2 T1 · risk reserve (% of cost, 5–10%)"})
viewof m2T2RiskPrem = Inputs.range([0.00, 0.20], {value: 0.01, step: 0.01, label: "M2 T2 · risk premium (£/call)"})
viewof m3RiskPrem   = Inputs.range([1, 50],      {value: 10,   step: 1,    label: "M3 · risk premium per task (£)"})
viewof ceilMult     = Inputs.range([3, 5],       {value: 4,    step: 0.5,  label: "M5 · ceiling (× floor)"})
riskPremium = (score) => {
  const pts = [[1, 0.05], [3, 0.10], [6, 0.20], [8, 0.40], [10, 1.00]];
  if (score <= 1) return 0.05;
  if (score >= 10) return 1.00;
  for (let i = 0; i < pts.length - 1; i++) {
    const [x0, y0] = pts[i], [x1, y1] = pts[i + 1];
    if (score >= x0 && score <= x1) return y0 + (y1 - y0) * (score - x0) / (x1 - x0);
  }
}
autonomyMod = (lvl) => (lvl === "L4" ? 1.20 : lvl === "L5" ? 1.40 : 1.00);
overlay = (base) => base * (1 + riskPremium(riskScore)) * autonomyMod(autonomy);

humanMonthly = fteCount * fteCost / 12;

// Tier-to-Model Mapping (CoE reference doc §5.4) — which of the five models
// are actually offered under each deployment tier.
TIER_MODELS = ({
  "Tier 1 · Internal Use":        ["M1 Per Seat", "M2 Usage"],
  "Tier 2 · Platform Services":   ["M2 Usage", "M3 Task", "M4 Hybrid"],
  "Tier 3 · Digital Labor":       ["M1 Per Seat", "M3 Task", "M5 Outcome"],
})
activeModels = TIER_MODELS[dealTier];

// M2's formula depends on which tier it's playing in: Tier 1 = internal
// cost recovery (flat), Tier 2 = platform usage (per unit). It never
// appears in Tier 3, so this only matters when M2 is actually shown.
isM2Tier1 = dealTier.startsWith("Tier 1");

// The Tier 1 cost-recovery breakdown (Infrastructure + License + Support +
// CoE Overhead, plus a risk reserve on top) is the only real "cost of goods"
// here — the same product runs underneath every bar, so the vendor's cost to
// deliver it does not change with the commercial model chosen.
m2BaseCost    = m2Infra + m2License + m2Support + m2CoEOverhead;
m2RiskReserve = m2BaseCost * m2RiskRate;
vendorCost    = m2BaseCost + m2RiskReserve;

prices = {
  const m1 = overlay(fteCount * (fteCost / 12) * seatDiscount);

  // M2 · Tier 1: internal cost-recovery, flat regardless of volume. Takes the
  // generic risk/autonomy overlay since the formula has no risk term of its own.
  const m2Tier1Price = overlay(vendorCost / (1 - m2Margin));

  // M2 · Tier 2: platform usage, priced and billed per unit, scaling with
  // volume. Skips the generic overlay — like M3, its own per-unit risk
  // premium already prices that in, so applying both would double-count it.
  const m2UnitPrice  = (m2UnitCost + m2AllocOverhead) / (1 - m2T2Margin) + m2T2RiskPrem;
  const m2Tier2Price = volume * m2UnitPrice;

  const m2 = isM2Tier1 ? m2Tier1Price : m2Tier2Price;

  // M3 follows the CoE reference doc's task-pricing formula directly rather
  // than the overlay: Task Price = (Hours × Rate) × Complexity + Risk Premium.
  // It skips the generic risk/autonomy overlay because its own risk premium
  // term already prices that in per task — applying both would double-count it.
  const m3TaskPrice = (m3Hours * m3Rate) * m3Complexity + m3RiskPrem;
  const m3 = volume * m3TaskPrice;

  const m4 = overlay(m4BaseFee + value * m4Share);

  // M5 has its own floor/ceiling guardrails rather than the overlay
  const m4BaseOverlaid = overlay(m4BaseFee);
  const floor   = 0.8 * m4BaseOverlaid;
  const ceiling = ceilMult * floor;
  const m5raw   = value * m5Share;
  const m5      = Math.max(floor, Math.min(ceiling, m5raw));
  const m5bind  = m5raw <= floor ? "floor binds" : m5raw >= ceiling ? "ceiling binds" : "share applies";

  const withProfit = (model, price, note) => ({
    model, price, note,
    cost: vendorCost,
    profit: price - vendorCost,
    marginPct: price > 0 ? (price - vendorCost) / price : 0,
  });

  const all = [
    withProfit("M1 Per Seat", m1, `${(seatDiscount*100).toFixed(0)}% of human rate`),
    withProfit("M2 Usage",    m2,
      isM2Tier1
        ? `cost recovery @ ${(m2Margin*100).toFixed(0)}% margin`
        : `${volume.toLocaleString()} calls × ${gbpUnit(m2UnitPrice)}/call`),
    withProfit("M3 Task",     m3, `${volume.toLocaleString()} tasks × ${gbp(m3TaskPrice)}/task`),
    withProfit("M4 Hybrid",   m4, `base + ${(m4Share*100).toFixed(1)}% of value`),
    withProfit("M5 Outcome",  m5, m5bind),
  ];

  // Only show the models this deployment tier actually permits (CoE §5.4).
  return all.filter(d => activeModels.includes(d.model));
}

// Long-format cost/profit split for the stacked bar — each model's bar is
// drawn as vendor cost (bottom) + profit (top), summing back to its price.
segments = prices.flatMap(d => [
  {model: d.model, segment: "Vendor cost", y1: 0, y2: Math.min(d.cost, d.price)},
  {model: d.model, segment: "Profit",      y1: Math.min(d.cost, d.price), y2: d.price},
]);

gbp = (x) => "£" + Math.round(x).toLocaleString("en-GB");
// For sub-£1 unit prices (e.g. M2 Tier 2's per-call price), £0 from gbp()
// rounding is uninformative — show pence to one decimal place instead.
gbpUnit = (x) => x < 1 ? (x * 100).toFixed(1) + "p" : gbp(x);
palette = ["#3DC7FF", "#0073E6", "#663894", "#AA4B8B", "#EF5E82"];
costProfitPalette = ["#9AA5B1", "#1B998B"];

How “vendor cost” is estimated here

The vendor’s cost to serve is built from the CoE reference doc’s Tier 1 cost-recovery breakdown: Infrastructure + License + Support + CoE Overhead, plus a Risk Reserve (5–10% of that base cost). This total is the same figure across all five bars, because the underlying agent and workload don’t change — only the commercial wrapper around them. Any model-specific base/platform fee (M4) is assumed to cover its own overhead and is left out of this cost line, so profit here is a gross margin on cost of goods, not a fully-loaded operating margin.

How each bar is calculated

The risk and autonomy settings apply on top of M1, M2 and M4 as a single overlay — this is the framework’s “apply the premium on top of the model price” rule:

\[\text{overlay}(x) = x \times \big(1 + \text{risk premium}\big) \times \text{autonomy modifier}\]

where the risk premium runs from +5% (score 1) to +100% (score 10), and the autonomy modifier is ×1.00 up to L3, ×1.20 at L4, and ×1.40 at L5.

Model Monthly price (before overlay)
M1 Per Seat \(\text{FTEs} \times \dfrac{\text{FTE cost}}{12} \times \text{seat discount}\)
M2 Usage (Tier 1) \(\dfrac{\text{Infra} + \text{License} + \text{Support} + \text{Risk Reserve} + \text{CoE Overhead}}{1 - \text{margin}}\)
M2 Usage (Tier 2) \(\text{volume} \times \Big[\dfrac{\text{unit cost} + \text{allocated overhead}}{1 - \text{margin}} + \text{risk premium}\Big]\)
M3 Task \(\text{volume} \times \Big[(\text{hours} \times \text{hourly rate}) \times \text{complexity} + \text{risk premium}\Big]\)
M4 Hybrid \(\text{base fee} + \text{value} \times \text{share \%}\)
M5 Outcome \(\max\big(\text{floor},\ \min(\text{ceiling},\ \text{value} \times \text{share \%})\big)\)

M2 has two personalities, and the deployment tier picks between them automatically. In Tier 1 it’s a flat internal cost-recovery number (no risk term of its own, so it does take the overlay) — notice it doesn’t move at all when you change the volume slider. In Tier 2 it’s a true per-unit usage price that scales with volume, and — like M3 — it carries its own risk premium, so it skips the generic overlay to avoid double-counting risk. M2 isn’t offered at all in Tier 3, so its fine-tune sliders simply have no bar to affect there.

M3 follows the same logic as M2 Tier 2: it’s the CoE reference doc’s task-pricing formula directly, with its own per-task risk premium, rather than the generic risk/autonomy overlay used by M1, M4 and M2 Tier 1. Applying the overlay and a per-unit/per-task risk premium would price risk twice.

M5 uses guardrails instead of the overlay: the floor is 80% of the (overlaid) M4 base fee — protecting your cost recovery — and the ceiling is a multiple of that floor, capping the customer’s exposure. Push the business value slider up and watch M5 climb off its floor, then slam into its ceiling: that is the whole story of outcome-based pricing in one slider.

These numbers are illustrative

The constants here are chosen to teach the shape of each model, not to quote a deal. Real engagements need the CoE templates, an audited baseline, and the token-distribution work from the next module.
