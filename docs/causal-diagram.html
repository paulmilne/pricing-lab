Causal Map

How the inputs actually drive cost, price and margin — and where they don’t yet, but arguably should

Every fix in this lab so far has come from tracing a chain of dependencies that wasn’t visible until something broke: volume meaning different things for different models, a mean-based price sitting next to a P90-based cost, a “risk score” that only touches three of the five models. This page draws that map out up front.

Reading the diagrams

Solid arrows are real dependencies — implemented in comparator.qmd’s code today, and you can move the corresponding slider and watch the number change. Dashed arrows are conceptual links — relationships that plausibly should exist given how the reference doc and the rest of this site talk about risk and variability, but which the model currently treats as independent sliders. They’re flagged here as a map of where the model is simplified, not a defect list.

The full picture was one dense diagram; it’s split into two smaller ones below — drivers (the qualitative/shared inputs) and computation (how those drivers turn into price, cost and margin) — so each stays readable on its own.

The wider view: a causal loop diagram

The four diagrams above are calling sequences — acyclic maps of how one slider’s value propagates into a number on the bar chart. They deliberately stop at the edge of the spreadsheet. But the business those numbers describe is not acyclic: price feeds margin, margin funds capability, capability raises the value delivered, and that in turn changes what a customer will pay. Those are feedback loops, and they’re invisible in a DAG.

This last diagram is a proper causal loop diagram (CLD). It doesn’t correspond to any code in comparator.qmd — nothing here moves when you drag a slider. It’s a model of the operating environment the lab sits inside, drawn to show where the reinforcing and balancing pressures actually are.

Reading a causal loop diagram

Each arrow carries a polarity. A + means the two variables move the same way (more of the cause → more of the effect, all else equal); a − means they move opposite ways. Trace a loop and count the − signs: an even number (including zero) makes it a reinforcing (R) loop — a virtuous or vicious cycle that compounds; an odd number makes it a balancing (B) loop — one that pushes back toward equilibrium. Node colour groups variables by domain: customer, commercial, delivery / adoption, cost, and market.

The loops, one at a time

Loop Type Chain What it means for pricing
R1 · Value flywheel Reinforcing value → willingness-to-pay → price → margin → reinvestment → value The core case for value-based (M4/M5) pricing: capturing more of the value you create funds the capability that creates more value. Left unbalanced it compounds.
R2 · Land & expand Reinforcing value → trust → autonomy (L1→L5) → volume → proof → (trust / new engagements) → volume → value Trust earned at low autonomy is what lets you move a customer up the tier ladder; each delivered task is a reference that widens the footprint. This is the growth engine the tier model is built around.
B1 · Token-cost squeeze Balancing volume × complexity → token consumption → P90 compute cost → margin (−) Growth is not free: more volume and harder tasks push the tail of the cost distribution, which is exactly why the cost side is priced at P90, not the mean.
B2 · Efficiency response Balancing margin (−) → optimisation (−) → compute cost → margin A thin margin creates pressure to optimise models and prompts, pulling compute cost back down — the self-correcting counterweight to B1.
B3 · Value-share / churn cliff Balancing value → aggressive value-share → perceived cost → churn risk → volume (−) The renegotiation cliff from the M5 Outcome Designer, seen as a loop: the more value you capture, the more the customer feels the price, and past a point they walk. It caps how hard R1 can be pushed.
B4 · Commoditisation Balancing margin → competitor pressure ← market maturity → price (−) Fat margins and a maturing market attract competitors whose pricing erodes yours — the long-run ceiling on any single deal’s economics.
B5 · Oversight capacity Balancing volume → human-oversight hours → spare capacity (−) → volume Agentic work still needs human oversight; as volume grows it consumes the very capacity needed to deliver it, unless autonomy (R2) raises the ceiling.

The interesting tension is between the two reinforcing engines (R1, R2) and the four balancing loops that constrain them. R1 says capture more value; B3 and B4 say not too much, or you’ll lose the customer or the market. R2 says grow volume; B1 and B5 say volume has a cost and a capacity ceiling. A durable pricing strategy is essentially a choice about which balancing loop you let bind first.

Known gaps (dashed edges above)

These are places the model treats inputs as independent when a real pricing conversation probably wouldn’t — flagged here rather than fixed, since each is a judgement call about how much realism this teaching tool needs versus how many more sliders it should have.

Gap What’s missing
Task complexity → Token CoV m3Complexity scales M3’s price, but has no effect on either model’s token-cost variability, even though a more complex task plausibly has a fatter-tailed token distribution too.
Risk score → per-unit risk premiums The shared riskScore slider drives the generic overlay (M1, M2 T1, M4), but M2 Tier 2 and M3 have their own, entirely independent risk-premium sliders. Moving the shared risk score does nothing to them.
Token CoV / P90 → M5’s floor token-distribution.qmd explicitly teaches “set the floor on the P90/P95 cost, not a flat percentage” — but M5’s actual floor is 0.8 × M4 base fee, with no connection to any token-cost distribution at all.
Deployment tier → default recalibration Switching tiers changes which models are shown, but doesn’t adjust any default slider values — a Tier 3 (Digital Labor) scenario and a Tier 1 (Internal Use) scenario keep the same defaults even though the underlying engagement shape is usually very different.
